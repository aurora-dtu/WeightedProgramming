4. Operational Semantics via Weighted Decision Processes🔗

In this section we introduce an operation semantics for wGCL by way of a weighted decision process (WDP).

🔗structure
WDP.{u_1, u_2, u_3} (𝒲 : Type u_1) (S : Type u_2) (A : Type u_3)
  [Zero 𝒲] : Type (max (max u_1 u_2) u_3)
WDP.{u_1, u_2, u_3} (𝒲 : Type u_1)
  (S : Type u_2) (A : Type u_3) [Zero 𝒲] :
  Type (max (max u_1 u_2) u_3)

A weighted decision process (WDP) is a tuple 𝑀 = (𝒲,ℛ,S,A,τ) and is comprised of

  1. The monoid of weights 𝒲, a monoid with zero.

  2. The naturally ordered, 𝜔-continuous 𝒲-module ℛ of rewards, such that the natural order of ℛ is a complete lattice.

  3. The state space S, an arbitrary set.

  4. The action space A, an arbitrary set.

  5. the state transition τ : S × A → S → 𝒲, such that τ(𝑠,𝑎)(𝑠′) ≠ 0 for at most countably many 𝑠′.

  6. the reward function ρ : S → ℛ.

Fields

τ_countable : ∀ (s : S) (α : A), Countable ↑(Function.support (self.τ s α))

For the purpose of proofs, it turned out to be easier not to bundle the reward function ρ with the WDP.

In addition to this definition, we also introduce Conf.succs and Conf.succsₐ which rephrase the semantics using a more explicit set construction of successors, shown equivalent by Conf.succs_agree. This other formulation helps Lean's automation better identify the complete set of successors, crucial for showing properties such as countable successors Conf.succs_countable.

These define a Conf.τ a transition function for the WDP that is induced by Step referred to as wGCL.toWDP as per Definition 4.3. In these we also define ρ and ρ' as the scoring functions parametric over postweighting.

4.2. Minimal Weighted Rewards🔗

Following the path of MDP's, we introduce a notion of schedulers as per Definition 4.5. This includes two schedulers, Sched, and memoryless MSched. Additionally we make use of history length dependent schedulers defined in Definition A.16 named HSched that only considers the current state and length of the history.

variable {𝔖 : M.Sched} {ℒ : M.MSched}

From Definition 4.6 we define WDP.Path as nonempty lists of states. We define Path.of n s₀ as the set of parths starting in state s₀ with length n, mirroring the syntax \text{Paths}^{=n}(s₀).

variable {π : Path S}

From Definition 4.7 we define WDP.Path.Weight computing the product of transition weights between successive states of a given path π and a scheduler 𝔖. Since our product is not necessarily commutative we can't use Finset.prod and have to resort to List.prod with List.pairs, however, since we store the latest state in a path as the head, we have to compute this product in reverse and thus rely on List.rprod.

We call Path.of₀ n s₀ 𝔖 the set of paths of length n starting in state s₀ with non-zero weight according to 𝔖. The set Path.of₀, as opposed to Path.of which doesn't consider weights, is countable as shown by Path.of₀_countable.

Definition 4.8 defines three notions of weighted reward on WDP's:

  • WRew: weighted reward given a length n, an initial state s₀, and, a scheduler 𝔖

    ∑ i ≤ n, ω∑ π : Path.of₀ i s₀ 𝔖, π.val.Weight 𝔖 • ρ π.val.head

  • WRew': weighted total reward given an initial state s₀ and a scheduler 𝔖

    ⨆ n : ℕ, M.WRew ρ n 𝔖 s₀

  • MinWRew: minimal weighted total reward given an initial state s₀

    ⨅ 𝔖 : M.Sched, M.WRew' ρ 𝔖 s₀

Definition 4.9 phrases op the minimal weighted total reward in the shape of an prescoring transformer like wp. This definition allows us to compare exactly op with wp, namely stating that operational and denotational semantics agree, as per Definition 4.11. Ultimately this is shown later with wp_eq_op.
